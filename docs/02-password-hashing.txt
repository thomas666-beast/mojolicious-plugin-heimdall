PASSWORD HASHING
================

WHAT IT DOES
  Turns a plaintext password into a hash you can store in a database,
  and later checks a plaintext password against that hash.
  New hashes use Argon2. Existing Bcrypt hashes still verify.

SNIPPET
  use Mojolicious::Lite -signatures;

  plugin 'Heimdall';

  get '/demo' => sub ($c) {
    my $pw = $c->heimdall->password;

    my $plain = 'correct horse battery staple';
    my $hash  = $pw->hash($plain);

    my $ok_good = $pw->verify($plain,        $hash) ? 'yes' : 'no';
    my $ok_bad  = $pw->verify('wrong password', $hash) ? 'yes' : 'no';

    $c->render(text => "hash: $hash\n" .
                        "correct password accepted: $ok_good\n" .
                        "wrong password accepted:   $ok_bad\n");
  };

  app->start;

EXPECTED OUTPUT
  hash: $argon2id$v=19$m=65536,t=2,p=1$...
  correct password accepted: yes
  wrong password accepted:   no

WHAT TO STORE
  Store the $hash string exactly as returned. It contains the algorithm,
  salt, and parameters. One TEXT column of 255 characters is enough.

VERIFYING A LOGIN
  my $user = $db->find_user($username);
  if ($user && $c->heimdall->password->verify($c->param('password'), $user->{password_hash})) {
    # login OK
  }

UPGRADING OLD HASHES
  if ($c->heimdall->password->needs_rehash($user->{password_hash})) {
    my $new = $c->heimdall->password->hash($c->param('password'));
    $db->update_user($user->{id}, { password_hash => $new });
  }

SWITCHING ALGORITHM
  In plugin configuration:

    plugin 'Heimdall', {
      password_encoder    => 'Bcrypt',
      password_validators => ['Bcrypt'],
    };

  New hashes will be Bcrypt. Old Argon2 hashes will still verify if you
  keep 'Argon2' in the validators list.
