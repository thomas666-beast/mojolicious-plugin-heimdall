SESSION AUTHENTICATION
======================

Configure secrets on the application before serving any traffic:

  my $secret = $ENV{MY_APP_SESSION_SECRET} // '';
  die 'Configure MY_APP_SESSION_SECRET' if length($secret) < 32;
  app->secrets([$secret]);
  app->sessions->samesite('Lax');
  app->sessions->secure(1);  # HTTPS deployments; use HTTP only on local dev

Generate the secret with a cryptographically secure random generator and
keep it out of source control. Mojolicious's default is not a production
secret. Heimdall rejects default or insufficiently long signing secrets
when its session helpers are used in production mode.

Configure the user loader:

  plugin 'Heimdall', {
    auth => {
      load_user => sub ($app, $id) {
        my $user = $app->users->find($id);
        return $user && $user->{active} ? $user : undef;
      },
    },
  };

Here `users` is your app's database helper, not a Heimdall method. The
loader runs once per request when a session user is first requested.
Return undef if the user no longer exists or is disabled. Without a loader,
the guard only checks for a user ID in the signed session.

After validating the login form's CSRF token and verifying the password,
call `$c->heimdall->auth->login($c, $id)`. Use
`$c->heimdall->auth->return_to($c, '/account')` to consume the saved local
destination, then redirect. The guard saves destination paths for GET or
HEAD only. It does not save a request body or use the request host as a
redirect destination.

Protect pages with the guard, and enforce roles separately:

  get '/admin' => sub ($c) {
    my $auth = $c->heimdall->auth;
    $auth->require_login($c) or return;
    return $c->render(text => 'Forbidden', status => 403)
      unless $auth->current_user($c)->{role} eq 'admin';
    $c->render(text => 'Admin area');
  };

Use POST and framework CSRF validation for login and logout. Both methods
clear the previous CSRF token, so fetch a fresh form after either action.
Logout removes authentication data from the current browser cookie; it
cannot invalidate previously copied cookies. Use a server-side session
store or add a revocation check to the account lookup when immediate
invalidation is required.

For the complete working app, see examples/README.md and
examples/heimdall_demo.pl.
